# TongCraft 架构图风格（v2）

架构文档决定**画什么**，下列固定提示词决定**怎么画**。只把固定段、布局与关系指令、图内文字白名单交给生图模型；图名和设计依据留在文档里，不送去生图。

## 固定提示词（原样复用）

> 绘制一张横向 16:9 的技术架构图。画面直接从分区、节点和连线开始，不画整图标题、页眉横幅或标题占位。使用不透明的暖纸白底（#F6F2E7）、墨灰文字和主线（#28312F）、苔绿分区标签（#486846），铜橙只用于少量强调（#A65028）。四周留适当边距，不用颜色单独表达含义。
>
> 采用正面、平整、对齐网格的技术图版。系统边界用细框，节点用浅底直角卡片。Minecraft 的感觉只来自少量原创体素小图标，例如方块地图册、简化的合成台、叠放的区块瓦片。文字和连线保持平面。不要画人物、风景、游戏截图、官方标志或大面积方块纹理；不用像素字体写中文。
>
> 按布局指令安排阅读方向，默认从左到右。使用单向箭头，尖端接到目标卡片边缘；并列选项不得画成前后步骤。实线表示数据流，虚线表示控制；只在白名单列出图例文字时绘制对应图例。不编造节点、关系、性能数字或服务商。
>
> 图内只能出现「图内文字白名单」中的原文，逐项按指定位置与次数绘制，未指定次数时只出现一次。用清晰的无衬线字体，不增删字、不翻译、不改大小写。除此之外，画布任何位置都不要有字：不加标题、副标题、系列名、角标、署名、水印、解释文字或仿字，图标内部也不加字。没列出的文字就留白。准确性和缩小后的可读性优先于装饰。只输出图。

## 本次内容（每次替换）

- **图外信息**：在内容清单中写明图名、范围、设计依据和风格版本；在 Markdown 放图名和必要背景。不要把这部分送入生图提示词。
- **布局与关系指令**：标明各边界和节点的位置、每条箭头的起点、终点和线型，以及并列、可选、互斥关系。内部 ID 和布局说明不是图中文字。例如桌面端与 CLI 都调用同一核心；CPU、GPU 不互相连接，玩家网站不读取世界存档。
- **图内文字白名单**：逐项列出必要的节点、分区、连线和图例文字，写明原文、位置、出现次数（默认一次）。没有列出的文字一律不画。图小就缩小范围，不靠缩字号塞下整套系统。

## 入库前核对

使用[架构图 Skill](../.agents/skills/tongcraft-architecture-diagram/SKILL.md)逐图验收。有多余文字或错误时，由 agent 把候选图和纠错提示词发给图像编辑模型，再复查整图；不用遮罩、代码或人工修图。只有验收通过的 PNG 或 WebP 和同名内容清单（例如 `overview.png`、`overview.brief.md`）可放入 `docs/diagrams/` 并嵌入文档。架构事实仍以正文与 ADR 为准。
