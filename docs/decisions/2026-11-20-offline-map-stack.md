# ADR：离线渲染和静态地图的技术栈

提案时间：2026-11-20 10:42 +08:00。状态：建议作为 v1 实施基线，待维护者采纳；采纳时间：未定。关联：[详细设计](../design-v1.md)、[测试策略](2026-11-20-testing-policy.md)。不宣称已有兼容性或性能实测。

后续决定：[Tauri 2 离线制图客户端 ADR（已采纳）](2026-11-20-desktop-renderer.md) 已替代下表的单一 CLI 入口；共享 Rust 核心、CLI 和 CPU/可选 wgpu 后端按新决定执行。其余候选项仍保留原评审状态。

约束：只拿定期导出的世界快照，不碰在线服；目标是二维定位，不要求还原每个方块模型；需要 GPU 选项，但没有显卡也要能发布相同地图。

| 决策 | 选择理由 | 替代方案与接受的代价 |
|---|---|---|
| 单个 Rust CLI，内部模块分层；`clap`、`serde`、有界 Rayon 线程池 | 一套数据结构贯穿解析、CPU 基线、GPU 输入和产物；无需本地服务或跨进程搬运像素 | Go + 原生 GPU 辅助程序或 Java + LWJGL 都可行，前者多一个二进制协议，后者多一套 JVM 发布环境；Rust 代价是要自己验证新存档版本 |
| `wgpu` + WGSL，无窗口 compute，CPU 始终保留 | 可覆盖 Windows D3D12、Linux Vulkan，不锁 NVIDIA；整数着色便于逐像素比对 | CUDA 只在部署明确限定 NVIDIA 且性能确证后重议；仅 CPU 最简单，仍作为可独立发布的首个里程碑。不保证 `auto` 模式总选 GPU |
| 无损 PNG、固定 256 像素瓦片；静态目录，不引入服务端数据库 | 生成、检查、回滚均可在本机执行；无损图方便核对坐标和调色 | 单文件瓦片档案能减少对象数，但增加范围请求和增量发布复杂度；若对象数、上传时间或费用成为实测瓶颈，再比较打包。缓存索引采用本地 SQLite，不对网站开放 |
| TypeScript + Vite + Leaflet 1.9 稳定系列，直接使用 DOM，不引入 React | 平移、缩放和几十个机器标记无需 WebGL；固定版本随站发布，不依赖运行时第三方 CDN | MapLibre 适合后续大量矢量样式或倾斜视图；沿用 BlueMap 改动最少，但不能满足独立维护二维制图链的目标。代价是自行维护坐标兼容和地表样式 |
| 先发布普通静态目录；生产对象存储适配器后置 | 不让云厂商、账户或密钥成为本地样机前提 | 提前绑定 R2 可少一步部署决策，但当前未确认规模、预算和更新窗口；保留同源路径和 manifest 契约即可后接 |

验证：同机同输入对比 CPU / 硬件 GPU 的解码像素、全量与增量墙钟、峰值内存；用旧链接打开真实浏览器验证定位。推翻条件：无法可靠读取目标快照、整次出图超出维护者的时间窗口、对象数或存储成本超预算、出现必须实时或 3D 的需求。遇到其中一项，先定位具体瓶颈，再撰写替代 ADR，不同时重写整条链。
