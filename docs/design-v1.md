# TongCraft Map v1 详细设计

2026-11-20 · 设计评审稿，以下目录、命令、字段均为拟定接口，不是已实现功能。技术取舍见 [ADR](decisions/2026-11-20-offline-map-stack.md)。目标是持有同一快照、样式和版本的人能离线得到相同的地图像素；网站既不接触世界存档，也不需要 GPU。非目标：实时玩家、全方块模型、在线更新世界、自动探测所有模组的视觉样式。

## 1. 部署边界与命令

同一仓库交付桌面制图客户端、独立 CLI 和公开静态站。按[已采纳的桌面端 ADR](decisions/2026-11-20-desktop-renderer.md)，`renderer/` 提供不依赖窗口的 Rust 库及薄 CLI；`desktop/` 通过 Tauri 2 从后台任务调用同一库，向 TypeScript 界面报告进度；`web/` 提供静态地图，也供桌面端预览生成的瓦片。`styles/` 保存有版本的方块配色和维度规则，`fixtures/` 只放可公开的合成样本生成说明或代码。私有快照只读。生成物先在 `output/staging/<id>/` 内构建，本地缓存单独置于 `cache/`。

| 拟定命令 | 责任与失败约定 |
|---|---|
| `tc-map inspect --snapshot <dir> --config map.toml` | 输出维度路径、检测到的版本、区块编码、覆盖范围和候选硬件；不出图。切勿只凭文件夹名推定主世界；歧义要求显式映射 |
| `tc-map render --snapshot <dir> --config map.toml --backend cpu --release <id>` | `cpu/gpu/auto`；按输入差异构建完整候选版本。`--rebuild` 忽略缓存以便核验；损坏或不支持的数据返回非零，不能把残缺版本标成成功 |
| `tc-map verify --release-dir <dir>` | 校验版本、路径、清单、瓦片覆盖和标记字段，解码抽样 PNG 并检查尺寸；产物无标记与标记文件损坏须能区分 |

配置项：显式维度 ID 与存档相对路径、各维度切层策略、样式版本、内存预算、并发上限、输出目录。拒绝重复 ID、未知选项、路径越界、输入输出重叠和重用已有发布 ID。并发上限同时约束解压、着色和编码，避免每个阶段各占满一轮 CPU。首次实现不含云端上传命令。

## 2. 渲染内部契约

1. **读取**：`reader` 将合法输入转换成按世界坐标寻址的 section：维度、chunk X/Z、section Y、局部 palette 和 block-state 索引。只读取制图所需的地形、可选生物群系；不读取玩家或容器物品。区分未生成、正常、损坏、不支持四类。开发样本通过不等于同一导出内所有 chunk 版本都通过。
2. **提取表面**：`surface` 自上往下取样，不把 heightmap 当最终颜色。`styles` 将注册名和必要状态映射为不透明、透水层、跳过或回退类型。第一版取单一可见材质、水深和高度，不承诺多层玻璃物理混合；未知方块以固定醒目色输出，按名称汇总。主世界按地表、末地空白透明；下界在配置中显式选择 `surface`（可见屋顶）或 `below_y`（从指定 Y 向下），不在程序里硬编码哪个高度“就是交通层”。
3. **CPU/GPU 公用输入**：一张 256×256 输出图带一圈邻列，局部输入为 258×258。列存储拟用两个 `u32`：第一字为 16 位材质号、8 位水深、8 位标志，第二字为有符号高度的位表示；缺失以标志表示，绝不借用 Y=0。样式表超上限报错。首版只做一格邻域坡度，未生成的邻列取中心高度，不画虚假陡壁。CPU/WGSL 共用查色表、整数舍入和 RGBA 通道顺序。
4. **计算与编码**：`raster` 接收 `TileKey + columns + style`，返回确定长度的 RGBA8，不自己读盘。GPU 用 storage buffer、8×8 工作组起步，按实际设备限额合批，边界显式检查；一批读回一次，PNG 编码由 CPU 处理。严格 GPU 模式发现软件适配器、设备丢失或缺少计算能力即失败；自动模式记录降级原因，仅重算未完成批次。先用 CPU 做缩小层，固定 2×2 预乘透明度平均及整数舍入，避免透明边缘发黑。
5. **运行报告**（私有，不随站发布）：记录读取区块数、未知方块、脏瓦片数、实际设备、各阶段耗时、总墙钟与峰值内存。不得把 GPU 内核耗时当作整次出图时间。

### 存档读取选型：容器与 NBT 分开验证

- [Mojang 26.1 版本说明](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-1)记录了维度目录迁移：优先识别 `dimensions/minecraft/{overworld,the_nether,the_end}/region/`；旧导出分别识别 `region/`、`DIM-1/region/`、`DIM1/region/`。新旧布局同时出现时报歧义，不自动合并。命名空间和网站维度 ID 通过配置映射。
- 常规 `.mca` 候选采用 [`fastanvil::Region`](https://docs.rs/fastanvil/) 做容器读取，不依赖其高级 `JavaChunk` 模型承诺 26.x；地形字段用 [`fastnbt`](https://docs.rs/fastnbt/) + Serde 的最小结构，长整型数组按 NBT `LongArray` 解包。对负 section Y、无 data 的单值 palette、跨 long 的填充规则，按区块 DataVersion 和样本验证。区块坐标、palette 索引、声明长度和解压预算都须校验，超限终止并定位输入。
- 超大区块的外置标志不能当普通压缩类型：容器适配层需识别同目录 `c.<绝对chunkX>.<绝对chunkZ>.mcc`，而非 region 内局部坐标；缺失时报错。锁定依赖版本前以实际样本验证内部/外置数据及目标压缩类型，遇到不支持的编码明确拒绝。若适配不了外置读取，只替换容器层，不重写 NBT、着色或浏览器。

## 3. 坐标、缩放与静态协议 v1

原点永久固定。最高原生细节 `level=0`，1 方块/像素；`level=k` 表示 `2^k` 方块/像素，与 Leaflet 地图 zoom 的方向相反。在 `L.CRS.Simple` 下原生 `zoom=-k`，`getTileUrl` 将 zoom 映射为 level。原生最大 zoom 为 0，更近时放大已有图片，不请求负的 level；瓦片不循环。方块 `(X,Z)` 占 `[X,X+1) × [Z,Z+1)`；标记落在方块中心 `[-(Z+0.5), X+0.5]`。

`tx=floor(X/(256×2^k))`，`tz=floor(Z/(256×2^k))`，父索引用向下整除 2。例：`X=-1,Z=256` 在 level 0 的 `(-1,1)`，图内像素 `(255,0)`；level 1 的 `(-1,0)`。跨原点的区域缩到远景仍可能有四张瓦片，不假定顶层必为一张。

网站先 GET `/current.json`，例：`{"schema":1,"release":"demo-001"}`。每次打开页面固定该版本，后续资源都在 `/releases/demo-001/`；`manifest.json` 示例如下（仅示意范围，不是实际地图尺寸）：

```json
{"schema":1,"release":"demo-001","tileSize":256,"format":"png","markers":"markers.json","dimensions":[{"id":"world","bounds":[-512,-512,512,512],"maxLevel":2,"coverage":"coverage/world.json","tileTemplate":"tiles/world/{level}/{tx}/{tz}.png"}]}
```

`bounds` 是方块坐标 `[minX,minZ,maxXExclusive,maxZExclusive]`。每个维度的 coverage 按 `level → tz → 若干 [txStart,txEndExclusive)` 排列；显式空区不发图片请求，声明有图却 404 视为发布错误，不冒充空白。覆盖索引过大时按层拆分，保持版本一致。markers 为对象数组：`id,dimension,name,x,y,z,products`；`y` 可空，来自批准公开的机器表字段，缺失 X/Z 不生成标记，零值有效。网页只显示文本，不把表格字符串拼成 HTML。

链接保留现有 `#world_nether:X:Y:Z:200:0:0:0:1:flat`，只消费维度和 X/Z，Y 不参与平面投影；维度白名单、有限数字、参数长度均需校验，错误链接回到维度概览并提示。来源是官网机器表，而不是从已生成 HTML 反向抓取；建议官网构建显式导出公开 JSON，地图构建消费固定副本，二者之间没有运行时请求依赖。

## 4. 增量、失败恢复与发布

本地 SQLite 索引建议仅三类记录：输入文件摘要（含外置区块文件）、瓦片键及输入依赖摘要、成功完成的构建。按维度比较上次成功输入与新输入的并集，处理新增、修改、删除。更新一个 region 时，重算相交最高层瓦片和一圈受坡度影响的边界，再自底向上更新父层；瓦片变空时删除索引。样式、切层规则、像素算法版本及输入解码版本都是缓存键的一部分。缓存丢失可全量重建，不是唯一数据源。

一次只允许一个发布者；失败停留在 staging，不修改线上指针。复用未变文件也必须构造完整发布目录（本地可通过硬链接复用不可变文件，不能原地覆盖共享文件）。先发布且核验全部不可变资源，最后替换单个 `current.json`；入口重新验证，带版本目录长缓存。托管不支持单次原子替换时采用平台级部署切换，不逐文件覆盖当前版本。回滚只回拨入口，旧版本至少保留完整更新周期及在途客户端所需窗口。上传严格按公开文件白名单，排除原档、SQLite、报告、私有坐标与路径。

## 5. 实施顺序与决策门槛

| 顺序 | 最小交付和退出条件 |
|---|---|
| A. 读档样机 | 用实际导出抽查三个维度和负坐标；记录 DataVersion 与压缩类型，用已知方块和机器坐标验证列高度、材质、下界切层。未过关不引入 GPU |
| B. 纵向走通 | CPU 生成小片 PNG 和清单；静态站定位一条官网旧链接。以可公开的小型有效存档跑一次真实 CLI → HTTP → 浏览器流程。保持 CI 不依赖私人快照 |
| C. GPU 后端 | 在目标硬件显式选择 GPU；同一输入解码像素与 CPU 完全一致。多次比较全量/增量端到端墙钟、中位数及峰值内存，单列读回成本；若无稳定净收益，不让 `auto` 默认使用 GPU |
| D. 增量发布 | 同一快照“增量 vs 从零”像素及覆盖一致，含删除和边界；注入失败不切换版本。测真实更新窗口、对象数和上传量，再决定是否接 R2 或改打包格式 |

不要为模块逐一增加模拟测试。先验证 A、B 和一条关键行为；必要时将已有真实小样扩展到 C、D。目标 GPU、代表性样本、下界默认层、更新预算尚未确认，因此不承诺倍率、兼容范围或云账单。参考：[wgpu 原生后端](https://docs.rs/wgpu/)、[Leaflet 平面坐标说明](https://leafletjs.com/examples/crs-simple/crs-simple.html)。
