# TongCraft 架构图

按[架构文档](../../../docs/architecture.md)与相关 ADR 确定内容，按[固定风格提示词](../../../docs/architecture-diagram-style.md)绘图。图不是架构依据。将图名和背景说明写在图外的 Markdown；Minecraft 风格只体现在图标、配色和排版。

## 1. 准备候选图

- 从设计提取必要的边界、节点、数据/控制关系和连线方向；锁定本次文字白名单（逐项写原文、位置、次数，默认一次）。只纳入图中必须承载信息的节点、边界、箭头和图例标签，不为迁就生成结果临时加词。
- 使用支持的生图工具。在 Dim 中先用 `dim modality list --json` 查看默认能力；把固定风格段原样拼上精简的布局及连线指令、完整白名单，再调用 `dim image generate --prompt "$prompt" --out-dir "$runDir" --json`。不要传整份内容清单：图名、内部风格名、ID、依据和说明都不作为图中文字提供。若已有待修的候选图，直接开始验收，不再调用生图。
- 在忽略的 `.local-tests/architecture-diagrams/` 下为每次任务建独立目录作为 `runDir`，每轮使用工具返回的新文件路径，不覆盖原图。确认生图或编辑返回成功且实际有图片，再进行检查。

## 2. 逐张验收

1. 由主 agent 直接打开候选图检查，不使用 OCR。先逐区抄录实际看到的文字，再比对白名单的原文、位置与次数。检查四边、留白区、卡片、图标内部、连线和图例；标题、横幅、签名、水印及不可辨认的仿字都不允许。只忽略同一标签因排版产生的换行、空白差异，不忽略标点、大小写、错字或重复。
2. 核对每条箭头的起点、终点、方向、线型、并列关系和边界，检查暖纸底、文字对比和文档常用宽度下的可读性。每次模型编辑后重新检查整张图，不只检查修改区；与编辑前的图对照，确认本来正确的标签和连线没有改坏。
3. 主 agent 初检通过后，请另一位只读 agent 独立打开同一候选图，按上面两步复核。提供候选图、白名单和预期连线清单；若有编辑也提供前一版，但不提供初检结论。请复核者报告实际看到的文字、连线和有疑问的位置。只有两次视觉检查都通过才放行；有分歧、不可辨认内容或无法独立复核时，不得入库，可明确标为未验收预览。

## 3. 由 agent 自行局部纠错

- 验收失败时，由 agent 用自然语言说明问题的位置、要删除的文字或要替换成的准确标签，以及必须保留的构图、标签和连线。位置写在提示词里，不作为遮罩。删字时要求模型恢复邻近纸色，不留下笔画或补上新文案。
- 将当前候选图和纠错提示词直接提交给图像编辑模型：`dim image edit --image "$candidate" --prompt "$fix" --out-dir "$runDir" --json`。只用这类模型请求改图；不传遮罩，不写代码擦除、覆字或裁切，也不让维护者手动编辑。不改用整图生图来修候选图。
- 对模型的新输出重新验收整图。若编辑误改了原本正确的内容，基于编辑前的候选图调整提示词再请求模型。每张图最多调用 3 次编辑；仍有额外文字、不可辨认文字、缺项或关系错误就停止并说明原因，不通过改白名单放行。

## 4. 放行

仅在文字和架构验收均通过时，将最终 PNG 或 WebP 与同名 `.brief.md` 放入 `docs/diagrams/`。清单保留设计依据、风格版本、白名单和验收方式；正文相对路径嵌图，图外写标题和说明。仅做预览或验收未通过时不替换正式图，不把中间候选纳入文档。
